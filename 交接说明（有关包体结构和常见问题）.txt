四、环境要求
======================================================================

- Windows 10/11 x64（tools/llama-vulkan 里的 exe 是 Windows 构建，Mac/Linux 不能直接用）

- 重训：NVIDIA 显卡，显存约 8GB（开发机 RTX 5060 Laptop 8GB），内存 32GB
- 首次安装依赖需要联网


======================================================================
五、首次安装
======================================================================

打开 CMD，执行：

  cd /d D:\jiami\project
  python -m venv .venv
  .venv\Scripts\pip install -r requirements.txt

只跑演示，装完上面这些就够了。
如果只是应用 2026-11-09 更新包，通常不需要重装依赖；保留原 .venv，
除非 requirements.txt 有新增依赖。

如果要重训，再装训练依赖（版本为开发机实测，供参考）：

  .venv\Scripts\pip install torch --index-url https://download.pytorch.org/whl/cu128
  .venv\Scripts\pip install transformers peft datasets accelerate

注意：本包不包含 .env，也没有任何 API key。


======================================================================
六、启动（三个窗口）
======================================================================

窗口 1：本地小模型（必须先启动）

  cd /d D:\jiami\project
  ..\tools\llama-vulkan\llama-server.exe -m ..\models\qwen2.5-1.5b-ft-q4_k_m.gguf -ngl 99 -c 4096 --host 127.0.0.1 --port 8080

看到监听 8080 即成功。没有 Vulkan 显卡时把 -ngl 99 改成 -ngl 0 走 CPU。

窗口 2：后端

  cd /d D:\jiami\project
  .venv\Scripts\python -m uvicorn app.main:app --port 8000

浏览器打开 http://127.0.0.1:8000

窗口 3（可选）：假云端，只用于没有 key 时联调单轮报告协议

  cd /d D:\jiami\project
  python tools\mock_cloud.py 8090

然后用假云端启动后端（先关掉窗口 2 的后端，再执行）：

  cd /d D:\jiami\project
  set DEEPSEEK_API_KEY=mock
  set DEEPSEEK_BASE_URL=http://127.0.0.1:8090/v1
  .venv\Scripts\python -m uvicorn app.main:app --port 8000

PowerShell 对应写法：

  $env:DEEPSEEK_API_KEY="mock"
  $env:DEEPSEEK_BASE_URL="http://127.0.0.1:8090/v1"

假云端只返回固定报告和固定缺口（缺口写在报告第五节），用来验证单轮协议和界面，
不能用于效果评价。

使用真实 DeepSeek：

  cd /d D:\jiami\project
  copy .env.example .env
  notepad .env

在 .env 里填 DEEPSEEK_API_KEY，然后重启后端。
不要把 .env 发给别人或提交到仓库。

七、关闭服务

八、重训与评测
======================================================================

完整命令见 project/README.md 的“微调”和“评测”两节。

重训流程：
  1. python train/prepare_sft.py
  2. python train/lora_sft.py --base ... --out ... --epochs 3 --max-length 1024
  3. python ..\tools\llama-src\convert_hf_to_gguf.py <merged> --outfile ... --outtype f16
  4. ..\tools\llama-vulkan\llama-quantize.exe <f16.gguf> <q4_k_m.gguf> Q4_K_M

开发机实测：600 条训练集约 37 分钟，train loss 0.0046，valid loss 0.00044。
LoRA 参数：r=16、alpha=32、dropout=0.05、lr=2e-4、3 epochs、batch=1、
梯度累积 8、seq=1024、bf16。

三层评测：

  python eval/run_extraction.py --data data/synth_test.jsonl --out results/xxx.json
  python eval/run_privacy.py --results results/xxx.json --out results/privacy_xxx.json
  python eval/run_utility.py --results results/xxx.json --out results/utility_xxx.json

离线自检（不需要模型和 key）：

  python smoke.py

检索评测结果见“九、结果口径”；具体命令见 project/README.md。

======================================================================
十一、常见问题
======================================================================

Q: 页面右上角本地模型徽标是红的？
A: 窗口 1 的 llama-server 没启动或端口不是 8080。

Q: 点“确认并分析”报 422？
A: 发送前扫描发现加密文本里还有真名或手机号等，按提示修改加密文本后重试。

Q: 点分析报 502？
A: 没有配置 DEEPSEEK_API_KEY，或云端地址/模型名不对；也可以先用假云端联调。

Q: 更新后接口还返回 rounds/gaps 吗？
A: 不返回。已改为云端单轮生成报告，信息缺口统一写在报告第五节。

Q: 微调脚本报找不到 D:\jiami\models\...？
A: 解压路径不是 D:\jiami，按第三节修改 --base / --out。

Q: 模型能换吗？
A: 可以。演示时把 llama-server 的 -m 换成其他 GGUF；
   健康徽标里的模型名由 .env 的 LOCAL_MODEL 控制，仅展示用。
