# 心理档案去标识化的大小模型协同系统 · 技术报告（初稿）

> 状态：实验版。已完成 LoRA 微调、抽取/隐私/效用/检索四层离线评测与单轮云端链路联调；
> 真实云端效用评测、独立测试集与真人盲评待补。
> 对应代码与复现命令见 `README.md`。

---

## 摘要

针对心理档案上传云端时的隐私矛盾，本文实现了一套**关系型去标识化 + 本地检索增强**的大小模型协同系统：
本地 Qwen2.5-1.5B 抽取人名、具体地点与账号，替换为 `人物A` / `地点A` / `账号A`，并把受控关系属性
（同桌、母亲、学校等）随 legend 发给云端；云端只看到脱敏文本与本地检索的公开参考资料，单轮生成五节评估报告，
信息不足统一写入报告第五节，不再让云端回询、小模型作答。最终报告在本地严格逐字回译。30 篇合成测试集上，
微调后的 1.5B 裸模型把实体召回从 72.7% 提升到 100%，直接泄漏率从 86.7% 降到 0%；脱敏文本无正则 PII 残留、
无别名残留，重识别 top-1 为 10.7%（随机基线 10%）；关键信息保留率 100%，平均文本长度降至原文的 82.2%。

**关键词**：去标识化；伪名化；大小模型协同；隐私护栏；重识别；检索增强；临床文本

## 1. 问题与目标

- 心理档案包含姓名、学校、住址、联系方式等直接标识符，直接交给云端大模型会造成不可控扩散。
- 直接删除或密码学加密会破坏上下文，云端无法完成评估。
- 目标：在不泄露直接标识符的前提下，尽量保留临床分析所需的语义与关系信息，并让所有替换可逆、可审计。

**非目标**：不保证密码学密文；不保证准标识符（年龄、年级、日期、罕见事件）完全消除；不防护本地设备被完全控制。

---

## 2. 威胁模型

### 2.1 保护对象

真实姓名与昵称、具体学校/单位、家庭住址、电话、微信/QQ、身份证、学号、邮箱。

### 2.2 对手

云端服务商及其日志与运维人员；传输链路窃听者；本地映射表泄露；被提示注入诱导、试图在报告中反推或编造身份的云端模型。

### 2.3 保证

1. 发往云端的请求体（脱敏文本 + legend + 公开参考资料）不包含映射表中的任何真名、别名、地址、账号与 `note`。
2. 映射表只存在浏览器与本地进程内存，不上传、不落盘。
3. 回译只在本地进行。
4. 小模型或云端失败时失败关闭，绝不降级发送原文。

### 2.4 不保证

准标识符组合重识别；页眉/页脚/批注/图片中的信息；治疗师主动泄露；本地设备被完全控制。

## 3. 方法

### 3.1 数据契约 v2

小模型只输出实体清单，不改写正文；替换由代码完成。

```json
{"entities":[{"placeholder":"人物A","category":"人物","relation":"同桌",
              "aliases":["王浩"],"note":"坐在来访者后排"}]}
```

- `placeholder`：`来访者` 或 `人物X/地点X/账号X`，同一实体全局唯一；
- `category`：人物 / 地点 / 账号；
- `relation`：只能取受控词表（人物关系、地点类型、账号类型），不确定填空；
- `aliases`：必须逐字出现在原文，代码用 `text.count()` 校验，找不到即丢弃；
- `note`：可含真名，只留在本地，永不发给云端。

代码侧还会做关系同义词归一（妈妈→母亲、手机号→电话、住址→家庭住址）、别名 sanity（拒绝"学校""朋友"
这类泛称与单字名）、同占位符冲突拆分、长别名优先替换。

### 3.2 规则兜底

在模型输出之上叠加确定性规则，覆盖模型易漏的格式：

- 账号正则：手机号、身份证、邮箱、QQ（含"QQ号"）、微信（含"微信号"）、银行卡、学号；
- 人物：`来访者/患者 + 姓名` 与 `角色词 + 姓氏 + 名` 两类模式，带边界词表；
- 地点：学校、医院、家庭住址、街道门牌，带上下文边界与停用前缀，避免把"建议学校加强关注"当成校名；
- 规则与模型冲突时以规则关系为准；模型把不同人合并进同一实体时按规则关系拆分。

### 3.3 发送前隐私护栏

1. 别名精确扫描：映射表中每个 `original` 与 `aliases` 都不得出现在脱敏文本；
2. 正则扫描：手机号、身份证、邮箱、QQ、微信、银行卡；
3. 占位符完整性：文本中的占位符必须在映射表中（`来访者` 豁免），未知占位符告警。

`/api/analyze` 在调用云端前强制执行上述 1、2 项；命中则返回 422，且不回显真名。这把隐私保证从"前端自觉"
变成"服务端强制"。

### 3.4 单轮云端评估

```text
本地 → 云端：脱敏文本 + legend + 编号参考资料
云端 → 本地：五节评估报告（Markdown，占位符原样保留，含第五节「信息缺口」）
本地：清理越界引用编号 → 严格逐字回译
```

早期版本采用"云端提问 → 本地策略裁决 → 云端第二轮"的回询协议。联调发现 1.5B 小模型对开放式缺口
大多无法给出有效回答，容易答非所问，第二轮的额外收益有限，因此收敛为单轮：信息不足由云端直接写进
报告第五节，不再形成交互回路。这样请求次数、失败点和隐私面都更小，报告结构也保持完整。

### 3.5 小模型微调

- 基座：Qwen2.5-1.5B-Instruct；LoRA r=16、alpha=32、dropout=0.05，target 覆盖 q/k/v/o 与 MLP 三矩阵；
- 600 条合成训练集、80 条验证集；只对 assistant 段计算 loss；
- 3 epochs、lr=2e-4、batch=1、梯度累积 8、seq=1024、bf16；RTX 5060 Laptop 8GB 约 37 分钟；
- train loss 0.0046，valid loss 0.00044；
- LoRA 合并后经 `convert_hf_to_gguf.py` 转 f16，再用 `llama-quantize` 量化到 Q4_K_M（935MB），
  以 llama.cpp Vulkan 后端部署。

### 3.6 本地知识库与 RAG

云端报告的专业性不能只靠提示词。系统在本机维护一个可审计的小型知识库：

- **来源**：WHO mhGAP-IG v2.0、WHO 抑郁/自杀事实清单、NICE NG222/CG113、中国成人失眠指南（2023）、
  国家卫健委严重精神障碍管理规范、精神卫生法、中国心理学会伦理守则、教育部相关政策、OpenStax 教材；
  受版权保护的专著不入库，只做书目推荐。来源评估表见 `data/kb/README.md`。
- **知识卡**：60 张转述摘要，覆盖风险评估、抑郁、焦虑、睡眠、家庭与关系、CBT、伦理法律、报告写作、
  大学生心理；每张卡标注 `source` 与 `source_detail`。
- **检索**：`app/kb.py` 实现零依赖中文 BM25（标题/标签/主题字段加权、汉字单双字切词、同义词扩展），
  同一主题最多 2 张、主议题最多 3 张，默认返回 6 张；出现自杀/自伤线索时强制包含风险评估卡。
- **注入**：知识卡编号后随脱敏文本放入云端提示词，要求模型用 `[n]` 引用、不得编造来源；
  生成后清理超出范围的引用编号。前端只展示标题、主题、来源、年份与公开 URL。
- **隐私**：检索查询只含脱敏文本与受控关系词；知识卡和来源元数据不含个人信息。

## 4. 系统实现

- 后端：FastAPI，无状态；`/api/extract`、`/api/guard`、`/api/analyze`、`/api/deanonymize`、`/api/health`。
- 本地推理：llama.cpp Vulkan 构建，微调 Qwen2.5-1.5B LoRA 合并后量化为 Q4_K_M，`temperature=0`，
  JSON schema 约束抽取输出。
- 前端：单页原生 JS；原文/脱敏对照、关系列、泄漏扫描结果、参考依据列表、
  加密版报告折叠区。
- 配置：`.env` 管理本地后端与 DeepSeek key；不写死密钥。

## 5. 实验

### 5.1 数据

- 模板合成，固定随机种子，全部姓名/学校/地址/账号均为虚构；
- 600 训练 / 80 验证 / 30 测试；文本全局唯一，三个划分无重叠；
- 覆盖：患者本人、关系人、多别名、学校/医院/地址、电话/微信/QQ/邮箱/身份证/学号、无隐私样本、泛称干扰；
- 每篇带金标实体、临床关键点、受保护泛化词、10 候选重识别攻击目标。

**局限**：微调只用 `synth_train`，`synth_valid` 只做监控，`synth_test` 只在评测时使用；但三者为同一模板分布，
测试集不是开放域独立分布。规则层还在测试错误上迭代过，因此所有满分都应读作分布内上界。

### 5.2 指标

| 层 | 指标 |
|---|---|
| 抽取 | JSON 合法率、契约违规数、实体精确率/召回率、关系准确率、来访者占位符正确率、过度脱敏率、直接泄漏率 |
| 隐私 | 残留正则 PII、别名残留、占位符完整性、重识别 top-1 |
| 效用 | 关键信息保留率、受保护泛化词保留率、长度比、对应表规模、云端报告关键点覆盖、rubric 分 |
| 检索 | 主题 Hit@1/Hit@3、MRR、平均参考条数、资料纯净度 |
| 成本 | 单篇本地推理时延、云端请求次数与 token |

### 5.3 抽取结果（30 篇）

| 条件 | JSON 合法 | 实体精确率 | 实体召回 | 关系准确率 | 来访者正确率 | 直接泄漏率 | 过度脱敏率 | 单篇耗时 |
|---|---|---|---|---|---|---|---|---|
| base Qwen2.5-1.5B（裸输出） | 100% | 96.5% | 72.7% | 88.1% | 96.3% | 86.7% | 4.4% | 3.34s |
| base + 规则兜底 | 100% | 100% | 100% | 100% | 100% | 0% | 0% | 4.71s |
| **微调 1.5B（裸输出）** | 100% | 100% | 100% | 100% | 100% | 0% | 0% | 5.16s |
| **微调 1.5B + 规则兜底** | 100% | 100% | 100% | 100% | 100% | 0% | 0% | 5.14s |

裸模型平均每篇契约违规从 1.77 条（base）降到 0（微调）；微调模型已经能独立完成契约要求的编号、关系与
别名逐字输出，规则层从"主要修复者"退化为"确定性保险"。单篇耗时增加约 1.8 秒，主要因为微调模型输出更完整
（实体更多、JSON 更长）。

### 5.4 隐私结果（微调 + 规则）

微调裸输出的结果与下表一致（直接泄漏率同样为 0），规则层没有额外贡献隐私指标。

| 指标 | 结果 |
|---|---|
| 残留正则 PII 比例 | 0% |
| 别名残留比例 | 0% |
| 占位符缺失 / 未知 | 0 / 0 |
| 直接泄漏率 | 0% |
| 重识别 top-1（随机猜测） | 10.7%（基线 10%） |
| 重识别 top-1（利用明文泄漏） | 10.7% |

重识别攻击共 84 个目标；在无别名泄漏时，攻击者只能靠准标识符猜，结果与随机持平。该结论只对合成数据成立，
不能外推到真实档案。

### 5.5 效用结果（微调 + 规则，离线）

| 指标 | 结果 |
|---|---|
| 加密文本关键信息保留率 | 100% |
| 受保护泛化词保留率 | 100% |
| 平均长度比 | 0.822 |
| 平均对应表规模 | 5.7 项/篇 |

关键点覆盖是"短语是否仍出现在脱敏文本"的字面统计，不等价于云端报告质量；云端报告覆盖与 rubric 分待补。

### 5.6 单轮链路联调

用微调模型 + 假云端验证：抽取人名、地点与账号实体且关系正确；本地检索命中参考资料并注入提示词；云端单轮报告返回后
完成越界引用清理与回译，报告第五节保留信息缺口；破坏性测试中把真名改回脱敏文本，`/api/analyze` 返回 422 拦截。
该测试只验证链路，不构成效果证据。

### 5.7 检索结果

14 条人工标注查询（风险、抑郁、焦虑、睡眠、家庭、伦理、大学生、报告写作等）：

| 指标 | 结果 |
|---|---|
| 主题 Hit@1 | 85.7% |
| 主题 Hit@3 | 100% |
| MRR | 0.917 |
| 平均参考条数 | 4.6 |
| 知识卡 | 60 |
| 资料纯净度（占位符/手机号/身份证） | 通过 |

该结果只衡量"能否把正确主题的资料放进提示词"，不衡量云端报告是否因此更专业；后者需要真实 key 与人工评分。
RAG 的隐私边界与来源评估见 `data/kb/README.md`。

## 6. 讨论与失败案例

- **微调收益显著但需谨慎解读**：裸模型召回 72.7% → 100%，契约违规 1.77 → 0，直接泄漏 86.7% → 0；
  但 valid loss 低至 0.00044，说明模型高度拟合模板分布，不能据此宣称开放域能力。
- **规则层的角色变化**：base 阶段规则是主要修复者（召回 72.7% → 100%）；微调后规则几乎不再改写，
  作用退化为确定性保险。这是"先规则兜底、再微调内化"的合理演进。
- **规则与测试同源的风险**：规则是在测试错误上迭代的，`base + 规则` 的满分会高估规则在真实数据上的收益。
- **模型合并实体**：基座模型会把不同关系的人放进同一实体或复用占位符，代码按规则关系拆分；这是"模型抽取 +
  代码纠错"的典型协作点。
- **别名边界**：模型曾把"彭雨薇,曹文博"作为单个 alias 返回，导致两人同时泄漏；现在按分隔符拆分并逐字校验。
- **泛称误替换**：早期会把"学校""朋友"当实体；通过契约 sanity 与受保护词表消除。
- **准标识符**：年龄、年级、日期刻意保留用于临床分析，重识别风险用攻击实验量化，未做粗化。
- **RAG 的增益与边界**：检索能把指南原则与来源编号带进提示词，降低空泛建议；但知识卡只有 60 张，
  BM25 对隐晦改写可能漏检，且模型仍可能误用资料。引用编号清理只能阻止"编造编号"，不能保证每条建议都正确。

## 8. 复现

```bash
python data_gen/generate.py
python train/prepare_sft.py
python train/lora_sft.py \
  --base D:/jiami/models/Qwen2.5-1.5B-Instruct \
  --out D:/jiami/models/qwen2.5-1.5b-lora \
  --epochs 3 --max-length 1024

python ../tools/llama-src/convert_hf_to_gguf.py \
  D:/jiami/models/qwen2.5-1.5b-lora/merged \
  --outfile D:/jiami/models/qwen2.5-1.5b-ft-f16.gguf --outtype f16
../tools/llama-vulkan/llama-quantize.exe \
  D:/jiami/models/qwen2.5-1.5b-ft-f16.gguf \
  D:/jiami/models/qwen2.5-1.5b-ft-q4_k_m.gguf Q4_K_M

# 启动微调模型后
python eval/run_extraction.py --data data/synth_test.jsonl \
  --out results/ft_1.5b_raw_test30.json --label ft_1.5b_raw --no-rules
python eval/run_extraction.py --data data/synth_test.jsonl \
  --out results/ft_1.5b_rules_test30.json --label ft_1.5b+rules
python eval/run_privacy.py --results results/ft_1.5b_rules_test30.json \
  --out results/privacy_ft_rules.json
python eval/run_utility.py --results results/ft_1.5b_rules_test30.json \
  --out results/utility_ft_rules.json
python smoke.py
```

环境与启动见 `README.md`；威胁模型与整体设计的完整讨论见 `docs/整体框架与实施计划.md`（该文档中的回询协议为早期设计，当前实现已收敛为单轮）。
