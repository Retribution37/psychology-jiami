# 心理档案去标识化 · 架构说明与微调指南

> 读者：负责微调小模型的同学。
> 读完应知道三件事：小模型被要求做什么、输出必须长什么样、哪些错误会让整条链路坏掉。

---

## 0. 一句话概括

本地小模型把档案里的**具体人名 / 具体地点 / 号码账号**换成 `人物A` / `地点A` / `账号A` 这类代称，
代码据此生成对应表并做逐字替换；云端大模型只看到脱敏文本，写完评估报告后再按对应表回译。

**先记住这条边界**：小模型不写文档、不改写句子、不做摘要，**只输出一份 JSON 清单**。
替换动作由代码完成，这样"加密文本 = 原文的逐字替换"，回译才可证明。

---

## 1. 数据流

```text
.docx ──python-docx──▶ 纯文本 ──小模型──▶ JSON 实体清单
                                              │  校验（原文里找不到的别名丢弃）
                                              ▼
                                  代码逐字替换 + 生成对应表
                                              │
                                加密文本（可在前端人工修改）
                                              │
                              ┌───────────────┴────────────────┐
                              ▼                                ▼
                    DeepSeek（任务+加密文本+脱敏说明）    对应表留在浏览器内存
                              │
                     Markdown 报告（加密版，留档对照）
                              │
                     代码严格逐字回译
                              │
                       前端展示回译报告
```

---

## 2. 模块与边界

| 模块 | 负责 | 明确不做 |
|---|---|---|
| `app/docx_io.py` | `.docx` → 纯文本（段落 + 表格按文档顺序，行内用 ` \| ` 拼接） | 不处理页眉页脚、图片、批注、`.doc` |
| **`app/prompts.py`** | 小模型 / 大模型的提示词 | 提示词改动要与本文档同步 |
| **`app/anonymize.py`** | 校验实体 → 逐字替换 → 对应表 → 脱敏说明 → 回译 | 不调用模型、不碰文件 |
| `app/llm.py` | Ollama `/api/chat`（`format=json`）、DeepSeek `/chat/completions` | 不做重试、不做分块 |
| `app/main.py` | 四个接口，服务端无状态 | 不存文档、不存历史 |
| `web/index.html` | 上传 → 预览编辑 → 确认 → 展示 | 不直接调模型，全部走接口 |

## 3. 小模型的契约（微调的核心）

### 3.1 输入

- 一整篇纯文本，中文。段落之间空行；表格行是 `家庭住址 | 阳光小区3栋502` 这种形式。
- **不分块、不截断**（实验样本都短，几千字以内）。
- 不加任何额外包装，正文直接作为 user 消息。

### 3.2 输出

严格 JSON，不要 Markdown 代码块，不要任何解释文字：

```json
{
  "entities": [
    {"placeholder": "来访者", "category": "人物", "aliases": ["小明"], "note": "患者本人"},
    {"placeholder": "人物A", "category": "人物", "aliases": ["王浩", "小王"], "note": "同桌"},
    {"placeholder": "地点A", "category": "地点", "aliases": ["实验中学"], "note": ""},
    {"placeholder": "账号A", "category": "账号", "aliases": ["13800138000"], "note": "电话"}
  ]
}
```

| 字段 | 含义 | 约束 |
|---|---|---|
| `placeholder` | 替换后的代称 | `来访者` 或 `人物X/地点X/账号X`，同一实体全局唯一 |
| `category` | 类别 | **只能是** `人物` / `地点` / `账号`，写"人名""地址"会被丢 |
| `aliases` | 该实体在原文里的所有写法 | 必须**逐字**出现；代码会拿它 `text.count()`，找不到就丢弃 |
| `note` | 给人和给大模型的注释 | 不参与替换；**不会**发给云端（可能含真名，如"张三的母亲"） |

### 3.3 六条硬规则

1. **只有三类**：人物 / 地点 / 账号。日期、年龄、年级、症状、诊断、事件、情绪都不算。
2. **同一实体合并**：张三、小张、张同学 → 一个对象、一个占位符。
3. **占位符按类别编号**：人物A、人物B、地点A、地点B、账号A……
4. **别名逐字**：原文写"王浩"，别名就不能是"王浩同学"。
5. **患者本人固定叫 `来访者`**，不编号、不进人物序列。
6. **没有可脱敏内容**：输出 `{"entities":[]}`，不要硬凑。

### 3.4 该换 / 不该换

| 该换 | 不该换 |
|---|---|
| 张三、小张、王老师 | 朋友、同学、妈妈、家人（泛称） |
| 实验中学、XX小区3栋502、XX路12号、XX医院 | 学校、家里、公司（泛称） |
| 13800138000、微信号、QQ、身份证、学号、邮箱 | 16 岁、高二、2025 年 3 月（不是"名称/地点/号码"） |
| 具体单位名、机构名 | 抑郁症、失眠、自伤（临床信息，诊断要用） |

### 3.5 一个完整的"好输出"

输入：

```text
来访者小明，男，16 岁，实验中学高二学生。近一个月因同桌王浩的言语嘲讽情绪低落。
母亲李梅反映其夜间失眠，联系电话 13800138000。
家庭住址：阳光小区3栋502。
```

输出：

```json
{"entities":[
  {"placeholder":"来访者","category":"人物","aliases":["小明"],"note":"患者本人"},
  {"placeholder":"人物A","category":"人物","aliases":["王浩"],"note":"同桌"},
  {"placeholder":"人物B","category":"人物","aliases":["李梅"],"note":"母亲"},
  {"placeholder":"地点A","category":"地点","aliases":["实验中学"],"note":""},
  {"placeholder":"地点B","category":"地点","aliases":["阳光小区3栋502"],"note":"家庭住址"},
  {"placeholder":"账号A","category":"账号","aliases":["13800138000"],"note":"电话"}
]}
```

替换后（代码产出，不是模型产出）：

```text
来访者，男，16 岁，地点A高二学生。近一个月因同桌人物A的言语嘲讽情绪低落。
母亲人物B反映其夜间失眠，联系电话 账号A。
家庭住址：地点B。
```

## 4. 常见错误与代码里的后果

| 模型犯的错 | 后果 |
|---|---|
| 直接输出改写后的整篇文本 | JSON 解析失败 → 接口 502，流程中断 |
| 用 ```json 代码块包起来 | 解析失败 → 502 |
| 编造原文没有的别名 | 该实体被**静默丢弃** → 漏脱敏 |
| 把"学校""家里"当地点 | 全文变 `地点A`，可读性崩，大模型读不懂 |
| 同一个人的两种称呼给了两个占位符 | 回译后像两个人，报告逻辑错 |
| 把患者名字编号成人物B | 与"来访者"规则冲突，报告称呼混乱 |
| category 写"人名/地址/号码" | 该条被丢（只认三个中文词） |
| 用中文引号、尾逗号写 JSON | 解析失败 → 502 |
| 输出一大段分析再加 JSON | 解析失败 → 502 |

代码的容忍度是**很低**的：`_clean_entities` 只做"丢弃"和"合并"，**不会**替你纠错。
这就是微调要解决的重点——**格式稳定优先于召回**。

## 5. 下游怎么消费（改契约前先看这里）

| 位置 | 行为 |
|---|---|
| `app/anonymize.py::_clean_entities` | 丢弃原文找不到的别名；同 `placeholder` 的条目合并；`original` 取出现次数最多的别名 |
| `app/anonymize.py::anonymize` | 别名按长度降序替换，长串优先，避免"张三"先吃掉"张三丰" |
| `app/anonymize.py::legend` | 只把 `占位符 + 类别` 拼给云端，**绝不含真名和 note** |
| `app/anonymize.py::reverse` | 严格逐字把占位符换回 `original`；带空格、加粗的占位符**不会**被回译 |
| `app/main.py::extract` | 小模型 JSON 非法 → 502，**不会**降级发送原文 |

## 6. 怎么判断一个模型"能用"

准备 10–20 篇手写档案（覆盖：无隐私、大量别名、纯号码、机构名、泛称干扰），人工标出金标实体，然后算：

| 指标 | 定义 | 及格线（实验口径） |
|---|---|---|
| JSON 合法率 | 能 `json.loads` 的比例 | 100% |
| 契约违规率 | 类别错 / 别名不存在 / 同人双占位 | < 5% |
| 实体召回 | 命中金标实体数 / 金标总数 | ≥ 90% |
| 过替换率 | 泛称或非隐私被替换的比例 | < 5% |
| 回译成功率 | 报告中占位符被完整还原的比例 | 100%（给正确对应表时） |

`smoke.py` 就是按这个思路写的（用固定 JSON 跑通全链路），把它改成"读金标 + 算指标"即可当评测脚本。

## 7. 微调建议

**训练样本形式**（直接对齐线上调用）：

- system = `app/prompts.py` 里的 `EXTRACT_SYSTEM`
- user = 一篇档案纯文本
- assistant = 金标 JSON（压缩成一行，别带代码块）

**数据**：合成 300–800 条即可，每条刻意覆盖 1–3 个难点。比数量更重要的是难点覆盖：

1. 别名合并（同人多种叫法）——最常见、破坏最大；
2. 泛称不替换（学校/家里/妈妈）；
3. 机构名 vs 地名的类别判定；
4. 号码格式（手机号、身份证、微信号、混合中英文）；
5. 空输出（没人名没号码的纯情绪记录）。

**训练目标顺序**：先保 JSON 格式与六条规则，再提召回。宁可漏一个，也别把格式搞坏——格式坏 = 整条流程 502。

**不要**让模型学"改写正文"。它一旦开始润色，替换就对不上原文，回译必然断裂。

**运行参数**：`temperature=0`，Ollama `format:"json"`。

---

## 8. 如果要改契约

任何一条改动，同步这四处：

1. `app/prompts.py`（提示词规则）
2. `app/anonymize.py`（校验、替换、说明、回译）
3. `web/index.html`（对应表列、展示字段）
4. 本文档 + `README.md`

常见改动的影响：

- 加 `note` 展示 → 前端加列，`legend` 仍然不能带 note；
- 加"关系"类别 → `CATEGORIES` 与 `CATEGORY_LABEL` 同步，提示词加规则；
- 放开日期脱敏 → 提示词加一类，回译无影响（仍是字符串替换）；
- 改患者代称（"来访者"→"患者"）→ 提示词、前端文案、`legend` 里的固定项。
